  • CI 门禁齐全：31 jobs 含 clang-tidy、cppcheck、CodeQL 跨文件数据流、ASAN/UBSAN/TSAN、覆盖率 ratchet、告警棘轮、固件大小预算、Kconfig 覆盖矩阵、gitleaks、夜间长时模糊
  • 架构铁律零违规：依赖方向、God Object 禁令、热路径零动态分配（唯一 new 为对象池 placement new）、experimental 隔离——全部实测通过
  • 技术债标记极少：全仓仅 2 处真实 TODO，无 #if 0 死代码
  • 文档习惯：KNOWN_ISSUES.md、kernel_bug_audit、README 功能状态表、static_assert 配置护栏等工程化文档实践
  • 注释文化：整体注释率 13.6%，drivers 27.8%、tests 23.0%，注释写「为什么」而非复述代码

五、优先修复建议

  1. P0 · 清理构建目录：保留 build_tests 与当前主力构建，删除其余 43 个目录，回收约 1.3GB；后续统一一个命名（如 build/），靠 gitignore 兜底
  2. P0 · 删除 stale autoconf.h：rm -f config/autoconf.h config/autoconf.cmake，每次换板构建前重执行（坑位 P1），让 static_assert 护栏真正生效
  3. P1 · 拆分 load_and_exec：按 ELF 头校验 → 段布局 → 重定位 → 入口跳转拆为独立函数，目标 <150 行
  4. P1 · Cortex-M arch_impl 抽公共层：将 4 份副本中相同的 MPU/SysTick/IRQ 逻辑提取为共享 arch_common.hpp，差异部分留各变体
  5. P2 · README 数字校准 + .mailmap：CI jobs 改 31、测试数改 827；用 .mailmap 统一四个作者身份
  6. P2 · 下沉根 CMake 板级分支：18 处 BOARD 条件迁入各 board.cmake，根文件只留通用逻辑
方法论与局限
① 代码度量基于 git 跟踪文件（git ls-files），3rdparty/ 与构建产物排除；② 函数长度用「括号配平」启发式检测，已修正单行空函数体误报，可能漏计签名跨行的函数；③ 重复代码按「去注释去空白后 MD5」分组，仅统计 ≥8 行的函数体；④ 「屎山指数」为加权主观模型：架构纪律权重最高（AGENTS.md 铁律），工程卫生主要影响本地环境，故综合分 3.4 而非 6.0；⑤ 测试通过率取自行内 build_tests 实跑（827/827，12.17s）。
